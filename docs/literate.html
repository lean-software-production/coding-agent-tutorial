Key Concept

At its core, a single agent turn is just an API request to the model provider. You provide a prompt, and it provides a response.

Breaking Down the Code

Lines 19–22: the turn itself

This is the whole agent — one request, one response. Note that messages is a list: the API keeps no memory of its own, so every turn must resend the entire conversation. That single fact is what the next two iterations are built on.

Line 24: reading the reply

Replies arrive wrapped in choices, because a provider may return several candidate completions. We take the first and print its text.

Lines 15–17: one line of input

readline/promises lets us await the user's answer instead of nesting callbacks. rl.close() is what allows the program to exit at all — readline holds stdin open until released, and this iteration only ever reads one line.

Setup

Lines 10–13: pointing the client elsewhere

OpenCode Zen speaks the OpenAI wire protocol, so the standard openai package works unchanged — only baseURL moves. ?? fills in a default when the variable is unset.

Lines 4–8: a missing key

Checked here so it fails with a readable message, rather than as a 401 from deep inside the library.

Pressure Test: Run npm start, ask one question, then try to ask a follow-up. The program exits after the first answer, so there is no way to continue the conversation. This explains why the next iteration adds a prompt loop.

What the agent can do now

It can answer one question you type, using a real language model — a complete agent turn, start to finish.

Key Concept

The feeling of an interactive agent chat comes from a loop, but without memory of the conversation, the agent is not very helpful.

What Changed from Iteration 001

Lines 22–23, 31: the loop

Everything the previous iteration did once now happens over and over. rl.close() is gone from just after the question, because closing the reader is what ended the program after a single turn. The loop has no exit condition, which is honest: the spec says the only way out is Ctrl-C, and a while (running) flag would imply a door that does not exist.

Lines 25–28: still one prompt at a time

The request is rebuilt from scratch on every pass, and line 27 fills messages with only the prompt just typed. Nothing from earlier turns is sent. This is deliberate — it is the "stateless" in the iteration's name, and it is what the pressure test exposes.

Lines 17–20: leaving cleanly

Node's readline throws AbortError on Ctrl-C only when nothing is listening for SIGINT. Registering a listener does not catch that error; it takes the branch where no error is raised at all. process.exit(0) then gives the zero exit code the spec asks for.

Setup

Lines 10–15: the client and the reader

Unchanged from iteration 001, except that rl is now created once and outlives every turn.

Unchanged from iteration 001.

Pressure Test: Tell the agent your name, then ask what it is. It will not know. The loop works, but each turn is isolated, so nothing you said — or it said — survives into the next request. This explains why the next iteration sends the conversation history back to the model.

What the agent can do now

It holds a session open and answers question after question — and in the same breath shows the limit, forgetting an answer it gave one turn earlier.

Key Concept

Conversation memory means sending previous turns back to the model on each request. The model does not remember the session by itself; the program must keep the history and include it in the next API call.

What Changed from Iteration 002

Line 22: one array, outside the loop

This is the whole iteration in a single line. Iteration 002 built a fresh list on every pass; this one survives every turn, so the conversation can accumulate in it. The type annotation is not decoration — an empty [] would infer as never[] and refuse every later push.

Lines 26, 33–34: both sides of every turn

The prompt goes in before the request, the reply straight after. Line 34 pushes the message object the API returned, exactly as it arrived — it already carries role: "assistant", so there is nothing to construct. The shape the model sends back is the shape the next request needs.

Line 30: the whole history goes back

Shorthand for messages: messages. Every request now carries the entire session, growing by two entries a turn. The model still remembers nothing between calls; it simply re-reads the transcript we hand it each time.

What the agent can do now

It remembers the session, including its own answers — asked to pick a number and then asked what it picked, it says the same number twice. Before this iteration the second answer was a fresh guess.
