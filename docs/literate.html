Key Concept

At its core, a single agent turn is just an API request to the model provider. You provide a prompt, and it provides a response.

Breaking Down the Code

Lines 19–22: the turn itself

This is the whole agent — one request, one response. Note that messages is a list: the API keeps no memory of its own, so every turn must resend the entire conversation. That single fact is what the next two iterations are built on.

Line 24: reading the reply

Replies arrive wrapped in choices, because a provider may return several candidate completions. We take the first and print its text.

Lines 15–17: one line of input

readline/promises lets us await the user's answer instead of nesting callbacks. rl.close() is what allows the program to exit at all — readline holds stdin open until released, and this iteration only ever reads one line.

Setup

Lines 10–13: pointing the client elsewhere

OpenCode Zen speaks the OpenAI wire protocol, so the standard openai package works unchanged — only baseURL moves. ?? fills in a default when the variable is unset.

Lines 4–8: a missing key

Checked here so it fails with a readable message, rather than as a 401 from deep inside the library.

Pressure Test: Run npm start, ask one question, then try to ask a follow-up. The program exits after the first answer, so there is no way to continue the conversation. This explains why the next iteration adds a prompt loop.

What the agent can do now

It can answer one question you type, using a real language model — a complete agent turn, start to finish.
