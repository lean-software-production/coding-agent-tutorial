Key Concept

At its core, a single agent turn is just an API request to the model provider. You provide a prompt, and it provides a response.

Breaking Down the Code

Lines 4–8: fail fast on a missing key

Without this guard, a missing key surfaces as a confusing 401 from deep inside the OpenAI library. Failing here names the actual cause. Pulling the key into a variable also narrows its type: after the guard, TypeScript knows apiKey is a string, not string | undefined.

Lines 10–13: an OpenAI client pointed somewhere else

OpenCode Zen speaks the OpenAI wire protocol, so the standard openai package works unchanged — only baseURL moves. ?? supplies the default only when the variable is unset, which is what lets you swap models and endpoints without touching code.

Lines 15–17: one line of input

readline/promises lets us await the user's answer instead of nesting callbacks. rl.close() is what allows the program to exit at all — readline holds stdin open until released. We close it immediately, because this iteration only ever reads one line.

Lines 19–22: the turn itself

This is the whole agent. Note that messages is a list: the API keeps no memory of its own, so every turn resends the entire conversation. That single fact is what the next two iterations are built on.

Line 24: print the reply

The response arrives wrapped in choices — a provider could return several candidate completions. We take the first and print its text.

Pressure Test: Run npm start, ask one question, then try to ask a follow-up. The program exits after the first answer, so there is no way to continue the conversation. This explains why the next iteration adds a prompt loop.

What the agent can do now

It can answer one question you type, using a real language model — a complete agent turn, start to finish.
