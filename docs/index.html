Before we start

What are we doing today?

Fifteen lessons, and an agent that writes code you did not write.

We are

  • Building a coding agent, with the help of a coding agent.
  • Using no frameworks. No LangChain, no LangGraph, no Mastra.
  • Hands-on. Editor and terminal open.

We are not

  • Building the next great coding agent. (well, maybe?)
  • Adding every feature a product would need.
  • Learning about LLM architecture.

Why

  • Demystify it. Every moving part, in code you can read.
  • Learn the skill. Building agents is engineering now.
  • Know your tools. You use one every day. See what it does.

How you'll build it

Your coding agent coaches you through it

The repo ships a coach that reads the spec and walks you through it, one small step at a time. Your agent could write all fifteen lessons in minutes, and you would learn nothing. Go slow on purpose.

1
Open your agent in the repo and say “coach me”Codex, Claude Code or Pi.
2
It finds the first Todo in the ledgerdocs/iterations/README.md
3
It shows you one small change at a timeWhat the step achieves, then the file, the line and why. It waits for you.
4
You make the change, or say “jfdi”“jfdi” and it writes that step for you.
5
The acceptance test has to pass before DoneThe row only flips when the test is green.
6
Then it shows you what still breaksThe pressure test: the next lesson's reason to exist.

Lessons 1–3 · the whole idea

An agent is a while loop around one HTTP call

No framework, no orchestration engine. You keep a list of messages, you post it, you append what comes back.

Lessons 4–9 · the part everyone gets wrong

One tool use means calling the model twice

The model cannot run anything. It answers with a request — "use read_file" — and stops. Your code runs the tool, then calls the model a second time with the result.

Lesson 11 · guardrails

The model asks. Your code decides.

A habit in the prompt is a request. A rule in code holds whatever the model says.

What your agent already refuses

  • Files outside the project (lessons 4 and 8)
  • More than 25 rounds of tool calls, then it must answer (7)
  • Commands over 30 seconds, and more than 8000 characters of output (9)
  • rm, git push and .env, and bash never gets your key (11)

Patterns catch accidents, not intent

We blocked rm and asked it to clean up. It emptied both files with edit_file. Told to find a way, it used mv.

The real boundary is a sandbox that limits what the process can touch at all.

One check, before anything runs

const BLOCKED = [
  { pattern: /\brm\b/, reason: "deleting files is not allowed." },
  { pattern: /\bgit push\b/, reason: "pushing is not allowed." },
  { pattern: /\.env\b/, reason: ".env holds secrets." },
];
You: Push this branch to origin.
Tool: bash(git status && git push origin HEAD)
→ Blocked: pushing is not allowed.

Whose instructions are these?

A cloned repo's AGENTS.md and skills are someone else's words, given to an agent that has bash. Read them before you run an agent there.

Lesson 14 · skills

Instructions it loads when it needs them

A folder with a SKILL.md. The description is an advert; the rest is read only if the advert works.

.agents/skills/tdd/SKILL.md

---
name: tdd
description: Use when writing or changing code,
  to work test-first.
---

1. Write one failing test. Run it and read why it fails.
2. Write the least code that passes. Run it again.
3. Tidy up while the test stays green.

name and description are required. Optional: license, compatibility, metadata, allowed-tools.

1
Always: name and descriptionIn the system message, for every skill.
2
When it fits: the instructionsThe model calls skill("tdd") and your code returns the file.
3
If they ask: the files beside itScripts, references and templates, read with the tools it already has.

Where this came from

Commands already listed a description and loaded the body when called. Skills made that a portable standard.

16 Oct 2025: Anthropic announces Agent Skills. 18 Dec 2025: it publishes them as an open standard, agentskills.io.

Lesson 15 · before

One agent remembers everything it read

“Read every spec and summarize each in one line.” You wanted ten lines. The conversation kept every file.

Lesson 15 · one subagent

Let another agent do the reading, then forget

A subagent is the loop you already have, called as a tool. New conversation in, final text out.

Lesson 15 · three subagents

An agent whose tools include agents

“Use three subagents, one each for src, test and docs.” None of them needs the others, so they could run in parallel.

What to remember

A few tools and a while loop

Everything else you will ever read about agents is built on this.

1
An agent is a while loop around one HTTP callYou keep a list of messages, you post it, you append what comes back.
2
The model is stateless; the array is the memoryEvery turn re-sends the whole conversation, so what you put in it is the design.
3
The model never runs a tool. You do.Which is why a rule in code holds and a rule in a prompt might not.
4
Three tools is a coding agentread_file, edit_file, bash. Skills and subagents are two more, with the same shape.
5
Project instructions, skills and subagents manage one thingWhat is in the conversation, and when.
